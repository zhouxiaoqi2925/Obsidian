# 02 支付核心系统与分布式账务

## 2.5 分布式账务系统（核心重点）

### 2.5.1 账务系统四大特性

```text
              账务四性
┌──────────────────────────────────────┐
│  ① 强一致性  余额不差一分            │
│  ② 不可篡改  全链路审计 + 蚂蚁链存证  │
│  ③ 7x24h    全球多活切换 RPO=0      │
│  ④ 海量吞吐  单表万亿行              │
└──────────────────────────────────────┘
```

### 2.5.2 复式记账核心模型

```text
   资产 = 负债 + 所有者权益
   每笔交易: 借方 + 贷方 必相等
   账户余额 = ∑(贷方发生额) - ∑(借方发生额)
```

**账户分户表（核心）**：

```sql
-- 余额汇总表 (热数据, LSM-Tree)
CREATE TABLE account_balance (
    account_no    VARCHAR(32) PRIMARY KEY,
    user_id       VARCHAR(32) NOT NULL,
    currency      VARCHAR(8)  DEFAULT 'CNY',
    balance       BIGINT      DEFAULT 0,  -- 单位: 分
    frozen        BIGINT      DEFAULT 0,  -- 冻结金额
    version       BIGINT      DEFAULT 0,  -- 乐观锁
    gmt_modified  TIMESTAMP   NOT NULL,
    INDEX idx_user (user_id)
) PARTITION BY HASH(account_no) PARTITIONS 64;

-- 账户流水表 (冷数据, 列存)
CREATE TABLE account_journal (
    journal_id    BIGINT AUTO_INCREMENT PRIMARY KEY,
    account_no    VARCHAR(32) NOT NULL,
    txn_id        VARCHAR(32) NOT NULL,
    direction     TINYINT,  -- 1=借 2=贷
    amount        BIGINT,
    balance_after BIGINT,
    biz_type      VARCHAR(16),
    remark        VARCHAR(128),
    gmt_created   TIMESTAMP NOT NULL,
    INDEX idx_account_time (account_no, gmt_created)
) PARTITION BY RANGE(gmt_created) INTERVAL(1 MONTH);
```

### 2.5.3 账务核心：LSM-Tree + 强一致

```text
      OceanBase LSM-Tree 存储引擎
   ┌─────────────────────────────────┐
   │  MemTable  (内存, 跳表)         │  ← 写
   │      ↓ 转储                      │
   │  L0 SSTable  (最新, 紧凑)        │
   │      ↓ Compaction               │
   │  L1 SSTable                      │
   │      ↓ Compaction               │
   │  L2 SSTable                      │
   │      ↓                          │
   │  Major Compaction (合并)         │
   └─────────────────────────────────┘
        写: 顺序写 MemTable → 高吞吐
        读: 内存缓存 + Bloom Filter
```

**关键设计**：
- **写优化**：LSM 顺序写，单机 **>10 万** 写/秒
- **强一致**：Paxos 协议，3 副本多数派写入
- **合并读**：自动合并多版本，对外强一致读
- **合并余额**：异步合并流水到余额表（"打点"操作）

### 2.5.4 记账事务 Java 示例

```java
// 分布式事务: 转账 = 借A + 贷B, 必原子
@Transactional(rollbackFor = Exception.class)
public TransferResult transfer(String fromUser, String toUser, long amount) {
    // 1. 幂等检查 (幂等键)
    String idempotentKey = "TX:" + fromUser + ":" + toUser + ":" + amount;
    if (redis.setnx(idempotentKey, "1", 60) == 0) {
        throw new IdempotentException("DUPLICATE");
    }

    // 2. 借方 (扣款)
    int rows1 = accountBalanceMapper.debit(fromUser, amount, version);
    if (rows1 == 0) throw new InsufficientException();

    // 3. 贷方 (入账)
    int rows2 = accountBalanceMapper.credit(toUser, amount, version);
    if (rows2 == 0) throw new BizException("CREDIT_FAIL");

    // 4. 写流水 (异步)
    rocketMQ.asyncSend("ACCOUNT_JOURNAL_TOPIC", JournalEvent.of(...));

    return TransferResult.success();
}
```

### 2.5.5 防重与幂等设计

```text
幂等键生成原则:
  out_trade_no + merchant_id + amount  → SHA256 → 32B
  Redis SETNX (TTL 24h)
  OceanBase 唯一索引 (兜底)
```

```java
// 4 层幂等防线
public class IdempotentService {
    public boolean checkAndLock(String key) {
        // Layer 1: 本地缓存 (Caffeine, 1min)
        if (localCache.getIfPresent(key) != null) return false;

        // Layer 2: Redis SETNX
        Boolean ok = redis.opsForValue().setIfAbsent(key, "1", 1, TimeUnit.HOURS);
        if (Boolean.FALSE.equals(ok)) return false;

        // Layer 3: 分布式锁 (防并发)
        RLock lock = redisson.getLock("lock:" + key);
        if (!lock.tryLock(100, 5000, TimeUnit.MILLISECONDS)) return false;

        // Layer 4: OceanBase 唯一索引 (DB 兜底)
        return true;
    }
}
```

## 2.6 清分与结算

### 2.6.1 多边清分模型

```text
              一笔支付的多边清分
┌────────────────────────────────────────────┐
│  消费者支付 100.00 元                       │
│  ├─ 银行通道费      -0.20  (2‰)            │
│  ├─ 平台服务费      -1.00  (1%)            │
│  ├─ 商户应收        98.80  → T+1 结算      │
│  ├─ 分销商分润      -5.00  → T+1 结算      │
│  ├─ 税费            -0.60                   │
│  └─ 平台净收入      4.60                   │
└────────────────────────────────────────────┘
```

### 2.6.2 清结算时序

```text
T+0  实时:  支付成功 → 记入待清算账户 (不可提现)
T+0  日切:  24:00 批量清分 (按商户/分润/通道)
T+1  出账:  银行回单对账 → 差错处理 → 生成账单
T+1  结算:  提现到商户银行卡 (批量代付)
T+2  到账:  商户看到资金到账
```

### 2.6.3 清分核心 SQL（窗口函数）

```sql
-- 按商户维度清分 (OceanBase 兼容 MySQL 8.0)
SELECT
    merchant_id,
    SUM(CASE WHEN direction = 1 THEN amount ELSE 0 END) AS debit_total,
    SUM(CASE WHEN direction = 2 THEN amount ELSE 0 END) AS credit_total,
    SUM(amount * (CASE WHEN direction = 2 THEN 1 ELSE -1 END)) AS net_amount
FROM account_journal
WHERE gmt_created BETWEEN '2026-06-19 00:00:00' AND '2026-06-19 23:59:59'
  AND biz_type IN ('PAY', 'REFUND')
GROUP BY merchant_id
ORDER BY net_amount DESC;
```

public class ReconcileService {
    public void processDiff(ReconcileDiff diff) {
        // 1. 长款 (银行有, 内部无) → 补单
        if (diff.getType() == DiffType.BANK_ONLY) {
            orderService.createOrder(diff.getExternalTradeNo());
        }
        // 2. 短款 (内部有, 银行无) → 查通道

        else if (diff.getType() == DiffType.AMOUNT_MISMATCH) {
            manualQueue.push(diff);
        }
    }
}

### 2.8.2 退款核心代码

```java
public RefundResult refund(RefundRequest req) {
    // 1. 查原单
    PayOrder origin = payOrderMapper.getByOutTradeNo(req.getOutTradeNo());

    // 2. 校验金额
    if (req.getRefundAmount().compareTo(origin.getRemainAmount()) > 0) {
        throw new BizException("REFUND_EXCEED");
    }

    // 3. 写退款单 (幂等)
    RefundOrder refund = RefundOrder.builder()
        .outRefundNo(req.getOutRefundNo())
        .originalTradeNo(origin.getTradeNo())
        .amount(req.getRefundAmount())
        .status(RefundStatus.PROCESSING)
        .build();
    refundOrderMapper.insert(refund);

    // 4. 调原通道退款
    ChannelResult cr = channelAdapter.refund(origin, refund);

    // 5. 更新退款单 + 反向流水
    if (cr.isSuccess()) {
        refundOrderMapper.updateStatus(refund.getOutRefundNo(), RefundStatus.SUCCESS);
        accountService.credit(origin.getUserId(), req.getRefundAmount(),
                              JournalBizType.REFUND);
    }

    return RefundResult.from(cr);
}
```

## 2.11 小结
