# 01 整体架构与蚂蚁金服技术栈

## 1.2 单元化架构（Cell-Based Architecture）

蚂蚁自 2008 年起从"IOE 集中式"转向"分布式单元化"，**单元化是蚂蚁架构的 DNA**。

### 1.2.1 什么是单元化

将系统按**用户 ID/地域/业务**等维度拆分为多个**对等单元（Cell）**，每个单元具备完整的**写/读/计算**能力。**单元之间弱依赖、强对等**。

```text
            ┌──────────────────────────────────────────────┐
            │              GZone（全局中心）                 │
            │   跨单元数据汇聚/清算/对账/全局配置           │
            │   (例如：用户全局身份、跨单元转账汇总)         │
            └────────┬───────────────┬───────────────┬─────┘
                     │               │               │
        ┌────────────┴─────┐  ┌──────┴────────┐  ┌───┴──────────────┐
        │  CZone 单元 A     │  │  CZone 单元 B  │  │  CZone 单元 C    │
        │  (杭州-华东用户)  │  │  (上海-华南)   │  │  (深圳-西南)     │
        │  ┌──────────┐    │  │  ┌──────────┐  │  │  ┌──────────┐   │
        │  │ RZone 读写│    │  │  │ RZone 读写│  │  │  │ RZone 读写│  │
        │  │ (主)     │    │  │  │ (主)     │  │  │  │ (主)     │   │
        │  └────┬─────┘    │  │  └────┬─────┘  │  │  └────┬─────┘   │
        │  ┌────┴─────┐    │  │  ┌────┴─────┐  │  │  ┌────┴─────┐   │
        │  │ RZone 只读│    │  │  │ RZone 只读│  │  │  │ RZone 只读│   │
        │  └──────────┘    │  │  └──────────┘  │  │  └──────────┘   │
        └──────────────────┘  └────────────────┘  └──────────────────┘
        ▲  RZone = 分区，单元内 3 副本强一致 (Paxos)
        ▲  CZone = 容量区，承载一组 RZone
        ▲  GZone = 全局区，仅做跨单元逻辑
```

### 1.2.2 单元化核心规则（5 条铁律）

| 铁律 | 含义 | 违反后果 |
|---|---|---|
| ① ID 寻址 | 所有用户/商户 ID 唯一确定所属单元 | 数据不一致 |
| ② 流量封闭 | 单元内完成 95%+ 业务闭环 | 跨单元调用爆炸 |
| ③ 数据封闭 | 单元内数据自主，不跨单元读 | 延时抖动 |
| ③ 失败封闭 | 单单元故障不影响全局 | 雪崩 |
| ⑤ 容量对等 | 各单元容量对等可随时切流 | 切流不均 |

### 1.2.3 单元化代码示例（Go 寻址）

```go
// github.com/sofastack/sofa-bolt-go 寻址逻辑
package router

type CellRouter struct {
    rule *HashRule
}

func (r *CellRouter) Route(userID string, cellSet []string) (string, error) {
    // 1. 哈希分桶
    bucket := crc32.ChecksumIEEE([]byte(userID)) % uint32(len(cellSet))
    cell := cellSet[bucket]

    // 2. 检查 cell 健康度
    if !r.isHealthy(cell) {
        // 切流到次优 cell
        cell = r.fallbackCell(userID)
    }
    return cell, nil
}

func (r *CellRouter) isHealthy(cell string) bool {
    // SOFALookout 健康上报：CPU<70%, GC<10%, 错误率<0.1%
    metrics, _ := lookoutClient.Query(cell)
    return metrics.Healthy()
}
```

## 1.3 异地多活：LDC 架构

LDC = **Logical Data Center**，逻辑数据中心，物理上分布在全国/全球多个城市机房。

```text
       ┌────────┐  ┌────────┐  ┌────────┐
       │ 杭州   │  │ 上海   │  │ 深圳   │
       │ LDC-A  │  │ LDC-B  │  │ LDC-C  │
       │ 主写   │  │ 同城热备│  │ 异地灾备│
       └───┬────┘  └───┬────┘  └───┬────┘
           │           │           │
           ▼           ▼           ▼
       ┌────────────────────────────────┐
       │   全局调度 DNS+GSLB+VIP        │
       │   1) 就近接入                  │
       │   2) 故障秒级切换              │
       │   3) 蓝绿灰度发布              │
       └────────────────────────────────┘
```

**蚂蚁多活关键指标**（公开演讲披露）：
- RTO（恢复时间目标）< 30 秒
- RPO（恢复点目标）≈ 0（强同步复制）
- 单 LDC 可独立支撑 **100%** 全站流量

### 1.4.3 SOFARPC 服务发布示例（Java）

```java
// 支付服务发布端
@SofaService(interfaceType = PayService.class, uniqueId = "alipay")
@Component
public class PayServiceImpl implements PayService {
    @Override
    public PayResult pay(PayRequest req) {
        // 1. 限流
        RateLimiter limiter = RateLimiter.of("pay", RateLimiterConfig.custom()
            .limitForPeriod(100_000)
            .limitRefreshPeriod(Duration.ofSeconds(1))
            .build());
        if (!limiter.tryAcquire()) throw new BizException("RATE_LIMIT");

        // 2. 单元路由
        CellRouter.route(req.getUserId());

        // 3. 风控前置
        if (AlphaRiskClient.needBlock(req)) throw new BizException("RISK_BLOCK");

        // 4. 写账务
        return accountService.debit(req);
    }
}
```

### 1.5.1 消息中间件 AntQ/RocketMQ 事务消息

支付系统广泛使用**事务消息**保证"本地事务 + 消息投递"原子性：

```java
// RocketMQ 事务消息示例
TransactionMQProducer producer = new TransactionMQProducer("pay-group");
producer.setTransactionListener(new TransactionListener() {
    @Override
    public LocalTransactionState executeLocalTransaction(Message msg, Object arg) {
        try {
            // 1. 本地写账务 (OceanBase)
            accountService.debit((PayRequest) arg);
            return LocalTransactionState.COMMIT_MESSAGE;
        } catch (Exception e) {
            return LocalTransactionState.ROLLBACK_MESSAGE;
        }
    }

    @Override
    public LocalTransactionState checkLocalTransaction(MessageExt msg) {
        // 反查接口：定时回查本地事务状态
        PayRequest req = queryOrder(msg.getKeys());
        return req.isSuccess() ? COMMIT_MESSAGE : ROLLBACK_MESSAGE;
    }
});
```

> 蚂蚁内部称之为 **"消息事务一致性方案"**，是双 11 资金流不丢不重的核心保障。

## 1.7 全链路可观测：Trace + Metric + Log

### 1.7.1 SOFATracer 核心模型

```text
   TraceId (全局唯一)     ──┐
   │                       │
   ├─ Span1 (RPC A→B)     │
   │   └─ Span2 (RPC B→C) │
   │       └─ Span3 (DB)   │
   │                       │
   ▼                       │
   链路树 + Tag + Log      │
```

```java
// SOFATracer 注解
@Tracer(span = "payOrder", tags = {"biz:payment", "channel:alipay"})
public PayResult payOrder(PayRequest req) {
    Span span = Tracer.startSpan("payOrder");
    try {
        span.setTag("userId", req.getUserId());
        span.setTag("amount", req.getAmount());

        // 业务逻辑
        return doPay(req);
    } catch (Exception e) {
        span.setError(e);
        throw e;
    } finally {
        span.finish();
    }
}
```

## 1.9 关键架构原则（蚂蚁 12 条军规）

1. **一切皆服务**：连 DB 都按"服务化"思维
2. **无状态优先**：状态外置到 OceanBase/缓存
3. **异步解耦**：用消息做最终一致性
4. **幂等设计**：所有接口可重入
5. **防重入**：支付接口必带幂等键
6. **超时设置**：链路全配置，超时必传
7. **降级开关**：每个依赖都有开关
8. **限流熔断**：sentinel 默认全开
9. **监控告警**：4 个 9 SLA
10. **可灰度**：发布粒度到实例
11. **可回滚**：5 秒内一键回滚
12. **可观测**：链路 100% 埋点
