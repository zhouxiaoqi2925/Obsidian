## A 列:架构方案设计(结构 / 字段 / 字节)

### A1 技术选型 → 深度展开

#### 四级执行步骤
1. **业务规模评估** → DAU / QPS / 数据量 / 团队规模
2. **架构模式选型** → 单体 / MVC / 微服务 / Serverless
3. **中间件选型** → DB / Cache / MQ / 配置中心
4. **部署架构** → 物理机 / VM / K8s / 多云

#### 五级原子操作
- 决策矩阵评分:`架构模式 vs 团队规模 / QPS / 运维能力`
- ADR 文档:`docs/adr/0001-architecture-choice.md`
- POC 验证:`benchmark 压测 + 故障演练`
- 选型 Checklist:可扩展性 / 可维护性 / 招聘难度 / 生态

#### 六级参数项
| 参数 | 取值 | 业务影响 |
|------|------|---------|
| `QPS` | < 1K | 单体 Go 够用 |
| `QPS` | 1K-100K | 微服务 + 多实例 |
| `QPS` | > 100K | 分布式 + 分库分表 |
| `团队规模` | < 5 | 单仓单服务 |
| `团队规模` | 5-30 | 单仓多服务 + DDD |
| `团队规模` | > 30 | 多仓多服务 + 中台 |

#### 七级颗粒
- **单字段定义**:`UserID int64 \`json:"user_id"\`` — JSON tag 控制序列化字段名
- **单字符长度**:`varchar(32) NOT NULL UNIQUE` — 32 字符上限
- **单格式规范**:`uuid` 类型 vs `varchar(36)` — PG 推荐 `uuid` 原生类型
- **单属性约束**:`binding:"required,email,max=255"` — Gin binding 校验

### A2 领域建模 → 深度展开

#### 四级执行步骤
1. **业务事件风暴** → Domain Event / Aggregate / Bounded Context
2. **实体与值对象识别** → Entity / Value Object / Aggregate Root
3. **领域服务定义** → Domain Service / Repository / Factory
4. **限界上下文划分** → Bounded Context / Context Map

#### 五级原子操作
- `cmd/domain/` 建领域模型包
- 实体:`type User struct { ... }` + 行为方法
- 值对象:`type Email struct { value string }` + 校验
- 聚合根:`type Order struct { ... Items []OrderItem }`

#### 六级参数项
| DDD 元素 | Go 实现 | Java 实现 |
|---------|---------|----------|
| Entity | struct + ID | @Entity class |
| Value Object | struct 无 ID | @Value class |
| Aggregate Root | struct + 集合字段 | @AggregateRoot |
| Repository | interface | interface |
| Domain Service | struct + 业务方法 | @Service |

#### 七级颗粒
- **单实体**:`User{ID int64; Email string; ...}` — 行为: `ChangeEmail()`
- **单值对象**:`type Money struct{ Amount int64; Currency string }` — 不可变
- **单聚合根**:`Order{...; Items []OrderItem}` — 一致性边界
- **单领域事件**:`type UserRegistered struct { UserID int64; OccurredAt time.Time }`

#### 🔖 AI 直播平台实例
```go
// backend/internal/domain/user.go
package domain

import (
    "time"
    "github.com/google/uuid"
)

type User struct {
    ID           int64
    Username     string
    Email        string
    PasswordHash string
    Balance      Money  // 值对象
    Status       UserStatus  // 枚举
    CreatedAt    time.Time
    UpdatedAt    time.Time
}

// 行为方法(充血模型)
func (u *User) ChangeEmail(newEmail string) error {
    if !isValidEmail(newEmail) {
        return ErrInvalidEmail
    }
    u.Email = newEmail
    u.UpdatedAt = time.Now()
    return nil
}

func (u *User) DeductBalance(amount Money) error {
    if u.Balance.Amount < amount.Amount {
        return ErrInsufficientBalance
    }
    u.Balance = u.Balance.Sub(amount)
    u.UpdatedAt = time.Now()
    return nil
}

// 值对象
type Money struct {
    Amount   int64  // 单位:分
    Currency string // CNY / USD
}

func (m Money) Sub(other Money) Money {
    return Money{Amount: m.Amount - other.Amount, Currency: m.Currency}
}

// 领域事件
type UserRegistered struct {
    UserID     int64
    OccurredAt time.Time
}

func (u *User) Register() []DomainEvent {
    return []DomainEvent{
        UserRegistered{UserID: u.ID, OccurredAt: time.Now()},
    }
}
```

## B 列:业务编码实现(逻辑 / 控制流)

### B1 数据层 → 深度展开

#### 四级执行步骤
1. **ORM / SQL Mapper 选型** → GORM / sqlx / ent / sqlc
2. **实体映射** → struct ↔ table / JSON ↔ JSONB
3. **Repository 实现** → CRUD + 自定义查询
4. **事务封装** → UnitOfWork / Transaction Script

#### 五级原子操作
- `db.Create(&user)` — 插入
- `db.First(&user, "username = ?", name)` — 单条查询
- `db.Where("status = ?", 1).Find(&users)` — 条件列表
- `db.Transaction(func(tx *gorm.DB) error { ... })` — 事务

#### 六级参数项
| ORM | 性能 | 开发效率 | 类型安全 |
|-----|------|---------|---------|
| GORM | ⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| sqlx | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ |
| ent | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| sqlc | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

#### 七级颗粒
- **单字段查询**:`SELECT id FROM users WHERE email = ?` — 走唯一索引
- **单 SQL 拼接**:`db.Joins("LEFT JOIN orders ON ...").Where(...)` — 注意 N+1
- **单事务**:`tx.Create(&order); tx.Create(&orderItem); tx.Commit()` — 三步必须同事务
- **单批量**:`db.CreateInBatches(users, 100)` — 批量插入 100 条/批

```go
// backend/internal/repository/user_repository.go
package repository

import (
    "context"
    "gorm.io/gorm"
    "github.com/yourorg/ai-live/backend/internal/domain"
)

type UserRepository interface {
    Create(ctx context.Context, user *domain.User) error
    GetByID(ctx context.Context, id int64) (*domain.User, error)
    GetByEmail(ctx context.Context, email string) (*domain.User, error)
    Update(ctx context.Context, user *domain.User) error
    ListByStatus(ctx context.Context, status int, offset, limit int) ([]*domain.User, error)
}

type userRepo struct {
    db *gorm.DB
}

func NewUserRepository(db *gorm.DB) UserRepository {
    return &userRepo{db: db}
}

func (r *userRepo) Create(ctx context.Context, u *domain.User) error {
    return r.db.WithContext(ctx).Create(u).Error
}

func (r *userRepo) GetByEmail(ctx context.Context, email string) (*domain.User, error) {
    var u domain.User
    err := r.db.WithContext(ctx).Where("email = ?", email).First(&u).Error
    if err != nil {
        return nil, err
    }
    return &u, nil
}

// 复杂查询:用户 + 订单统计(避免 N+1)
func (r *userRepo) ListWithOrderStats(ctx context.Context, offset, limit int) ([]UserStats, error) {
    var stats []UserStats
    err := r.db.WithContext(ctx).
        Table("users u").
        Select("u.id, u.username, COUNT(o.id) as order_count, COALESCE(SUM(o.amount), 0) as total_amount").
        Joins("LEFT JOIN orders o ON o.user_id = u.id AND o.status IN (2, 3)").
        Group("u.id, u.username").
        Order("total_amount DESC").
        Offset(offset).
        Limit(limit).
        Scan(&stats).Error
    return stats, err
}

type UserStats struct {
    ID           int64
    Username     string
    OrderCount   int64
    TotalAmount  int64
}
```

### B2 业务层 → 深度展开

#### 四级执行步骤
1. **用例编排** → Application Service 编排领域对象
2. **业务规则校验** → 参数校验 + 状态机
3. **事务边界** → 哪些操作放同一事务
4. **事件发布** → 领域事件落 MQ

#### 五级原子操作
- Application Service 注入 Repository / Domain Service
- 参数校验:`if err := req.Validate(); err != nil { return err }`
- 事务:业务层显式 `tx := db.Begin()`
- 事件发布: `eventBus.Publish(UserRegistered{...})`

#### 六级参数项
| 场景 | 事务边界 |
|------|---------|
| 单表写入 | 不需要事务 |
| 多表写入强一致 | 同一事务 |
| 跨服务调用 | Saga / TCC |
| 异步通知 | MQ + 最终一致 |

#### 七级颗粒
- **单用例方法**:`func (s *OrderService) PlaceOrder(ctx, cmd) error` — 一个用例一个方法
- **单业务规则**:`if order.Amount > user.Balance { return ErrInsufficientBalance }`
- **单状态转换**:`if order.Status != StatusPending { return ErrInvalidStatus }`
- **单事务边界**:`tx.Create(order); tx.Update(user.Balance); tx.Commit()` — 三步同事务

#### 🔖 AI 直播平台实例
```go
// backend/internal/service/order_service.go
package service

import (
    "context"
    "github.com/shopspring/decimal"
    "github.com/yourorg/ai-live/backend/internal/domain"
    "github.com/yourorg/ai-live/backend/internal/domain/event"
)

type OrderService struct {
    orderRepo domain.OrderRepository
    userRepo  domain.UserRepository
    eventBus  event.Bus
    txManager TxManager
}

// 用例:下单
func (s *OrderService) PlaceOrder(ctx context.Context, cmd PlaceOrderCmd) (*domain.Order, error) {
    // 1. 参数校验
    if err := cmd.Validate(); err != nil {
        return nil, err
    }

    // 2. 业务编排(事务边界)
    var order *domain.Order
    err := s.txManager.WithTx(ctx, func(tx Tx) error {
        // 2.1 加载用户
        user, err := s.userRepo.GetByIDForUpdate(ctx, tx, cmd.UserID)
        if err != nil {
            return err
        }
        if user.Status != domain.UserStatusActive {
            return domain.ErrUserNotActive
        }

        // 2.2 余额校验
        if user.Balance.LessThan(cmd.TotalAmount) {
            return domain.ErrInsufficientBalance
        }

        // 2.3 创建订单
        order = domain.NewOrder(cmd)
        if err := s.orderRepo.Create(ctx, tx, order); err != nil {
            return err
        }

        // 2.4 扣减余额(充血模型)
        if err := user.DeductBalance(cmd.TotalAmount); err != nil {
            return err
        }
        if err := s.userRepo.Update(ctx, tx, user); err != nil {
            return err
        }

        // 2.5 发布事件(同事务)
        return s.eventBus.Publish(tx, event.OrderPlaced{
            OrderID:   order.ID,
            UserID:    user.ID,
            Amount:    cmd.TotalAmount,
        })
    })

    if err != nil {
        return nil, err
    }
    return order, nil
}

type PlaceOrderCmd struct {
    UserID      int64
    Items       []OrderItemCmd
    TotalAmount decimal.Decimal
}

func (c PlaceOrderCmd) Validate() error {
    if c.UserID <= 0 {
        return ErrInvalidUserID
    }
    if len(c.Items) == 0 {
        return ErrNoItems
    }
    if c.TotalAmount.LessThanOrEqual(decimal.Zero) {
        return ErrInvalidAmount
    }
    return nil
}
```

### B5 异常事务 → 深度展开

#### 四级执行步骤
1. **错误体系设计** → ErrorCode / 业务异常 / 系统异常
2. **重试策略** → 立即重试 / 退避 / 熔断
3. **幂等性实现** → Idempotency-Key / 唯一索引
4. **分布式事务** → 2PC / TCC / Saga / 本地消息表

#### 五级原子操作
- `errors.New("invalid_user")` — 标准错误
- `fmt.Errorf("place order failed: %w", err)` — 错误包装
- `errors.Is(err, ErrUserNotFound)` — 错误判断
- `retry.Do(ctx, 3, backoff, func() error { ... })` — 退避重试

#### 六级参数项
| 策略 | 适用 | 实现 |
|------|------|------|
| 立即重试 | 网络抖动 | `retry 3 times, 100ms` |
| 退避重试 | 上游故障 | `exponential backoff 1s/2s/4s` |
| 熔断 | 下游不可用 | `sony/gobreaker` |
| 幂等 | 重复请求 | `Idempotency-Key` |
| 分布式事务 | 跨服务强一致 | Saga + 补偿 |

#### 七级颗粒
- **单异常码**:`ERR_INSUFFICIENT_BALANCE = "10001"` — 业务错误码
- **单重试次数**:`retry: 3 times` — 配置化
- **单幂等键**:`Idempotency-Key: order-123456` — Header 传
- **单 Saga 步骤**:`compensate order + refund payment` — 补偿动作

```go
// backend/internal/errors/errors.go
package errors

import "errors"

var (
    ErrUserNotFound       = errors.New("user not found")
    ErrInvalidPassword    = errors.New("invalid password")
    ErrInsufficientBalance = errors.New("insufficient balance")
    ErrOrderNotPending    = errors.New("order is not in pending status")
)

// 业务异常 + HTTP 状态码
type BizError struct {
    Code    string
    Message string
    HTTPStatus int
}

func (e *BizError) Error() string {
    return fmt.Sprintf("[%s] %s", e.Code, e.Message)
}

var (
    ErrBizInvalidParam = &BizError{Code: "10001", Message: "参数无效", HTTPStatus: 400}
    ErrBizUnauthorized = &BizError{Code: "10002", Message: "未登录", HTTPStatus: 401}
    ErrBizForbidden    = &BizError{Code: "10003", Message: "无权限", HTTPStatus: 403}
    ErrBizNotFound     = &BizError{Code: "10004", Message: "资源不存在", HTTPStatus: 404}
)

// backend/internal/service/order_service.go - 幂等性实现
func (s *OrderService) PlaceOrderWithIdempotency(ctx context.Context, key string, cmd PlaceOrderCmd) (*domain.Order, bool, error) {
    // 1. 检查幂等键
    existing, err := s.idempotencyRepo.Get(ctx, key)
    if err != nil && !errors.Is(err, ErrIdempotencyNotFound) {
        return nil, false, err
    }
    if existing != nil {
        // 已处理过,返回缓存结果
        order, err := s.orderRepo.GetByID(ctx, existing.OrderID)
        return order, true, err
    }

    // 2. 处理订单
    order, err := s.PlaceOrder(ctx, cmd)
    if err != nil {
        return nil, false, err
    }

    // 3. 存储幂等键
    if err := s.idempotencyRepo.Save(ctx, key, order.ID, 24*time.Hour); err != nil {
        log.Warn("save idempotency key failed", "err", err)
    }
    return order, false, nil
}

// Saga 补偿:下单 → 扣款 → 库存 → 通知
// 任一步失败,反向补偿已成功的步骤
```

```go
            Help: "Total order errors",
        },
        []string{"error_code"},
    )

    DBConnections = promauto.NewGauge(

            Name: "db_connections_active",
            Help: "Active database connections",
        },
    )

// 使用
func (s *OrderService) PlaceOrder(ctx context.Context, cmd PlaceOrderCmd) (*domain.Order, error) {
    start := time.Now()
    defer func() {
        metrics.OrderDuration.WithLabelValues("place_order").
            Observe(time.Since(start).Seconds())
    }()

        metrics.OrderErrors.WithLabelValues(errCode(err)).Inc()
        return nil, err
    }
    metrics.OrdersTotal.WithLabelValues("success").Inc()
    return order, nil
```

```bash
VERSION=${1:-"v1.0.0"}

echo "Building backend:${VERSION}..."

# 1. 编译
CGO_ENABLED=0 go build \
    -ldflags="-s -w -X main.Version=${VERSION}" \
    -o bin/server \
    ./cmd/server

# 2. UPX 压缩(可选)
upx --best --lzma bin/server

# 3. 打包
tar czf openlive-backend-${VERSION}.tar.gz bin/ configs/ migrations/

# 4. 体积对比
ls -lh bin/server
echo "期望体积:< 30MB(纯 Go + UPX)"
```

### G3 灰度发布 → 深度展开

#### 四级执行步骤
1. **灰度比例** → 1% → 10% → 50% → 100%
2. **流量切换** → Nginx / Envoy / Service Mesh
3. **蓝绿部署** → 两套环境切换
4. **滚动升级** → K8s Deployment 滚动

#### 五级原子操作
- `kubectl set image deployment/backend backend=openlive:v1.0`
- Nginx 灰度:`upstream backend_v1 { server v1; } upstream backend_v2 { server v2; }`
- 蓝绿切换:`switch DNS / Load Balancer`
- 灰度判断:按 user_id 哈希 / 按地区 / 按版本

#### 六级参数项
| 策略 | 适用 | 切换粒度 |
|------|------|---------|
| 全量发布 | 低风险 | 秒级 |
| 灰度发布 | 中风险 | 1% → 100%(小时级) |
| 蓝绿部署 | 高可用要求 | DNS 切换(秒级) |
| 金丝雀 | 实验性功能 | 1% 流量验证 |

#### 七级颗粒
- **单灰度比例**:`10%` — 10% 流量走新版本
- **单流量切换**:`upstream backend { server v2; }`
- **单回滚步骤**:`kubectl rollout undo`
- **单冒烟测试**:`curl /healthz` — 部署后立刻验证

#### 🔖 AI 直播平台实例
```bash
# backend/scripts/deploy.sh
#!/bin/bash
set -e

NEW_VERSION=${1:-"v1.0.1"}
OLD_VERSION=$(cat /tmp/current_version)

echo "Deploying ${NEW_VERSION} (replacing ${OLD_VERSION})..."

# 1. 镜像准备
docker pull registry.openlive.com/backend:${NEW_VERSION}

# 2. 灰度发布(10%)
kubectl set image deployment/backend \
    backend=registry.openlive.com/backend:${NEW_VERSION}

# 3. 等待 5 分钟,观察监控
echo "Sleeping 5 minutes for canary monitoring..."
sleep 300

# 4. 检查错误率
ERROR_RATE=$(curl -s "http://prometheus:9090/api/v1/query?query=rate(order_errors_total[5m])/rate(orders_total[5m])" | jq '.data.result[0].value[1]')

if (( $(echo "$ERROR_RATE > 0.01" | bc -l) )); then
    echo "❌ Error rate too high: $ERROR_RATE, rolling back..."
    kubectl set image deployment/backend \
        backend=registry.openlive.com/backend:${OLD_VERSION}
    exit 1
fi

# 5. 全量发布成功
echo ${NEW_VERSION} > /tmp/current_version
echo "✅ Deploy ${NEW_VERSION} success"
```
