### 1.2 关键技术组件详解（云原生三层）

字节内部技术栈遵循 **"RPC 框架 + 网络库 + 服务治理"** 三层架构：

**应用层**：业务微服务 100% 使用 Kitex/Hertz，IDL 统一为 Thrift + Protobuf 双轨。**Sonic** 作为默认 JSON 编解码器，比 Go 标准库快 5–10 倍（JIT+SIMD），C++ 端用 sonic-cpp。

**框架层**：Kitex（Go RPC）和 Hertz（HTTP）共享 **Netpoll** 网络库，Netpoll 通过 epoll+共享内存（shmipc）压榨单机连接数（单实例可承载 100w+ 长连接）。Rust 侧对应 Volo + monoio。

**基础设施层**：注册中心、配置中心、限流熔断、监控告警全部以中间件形式注入框架，字节内部称之为 **"Kitex 中间件套件 (Suite)"** 模式，可被 Volo/Hertz 复用。

## 二、抖音的微服务架构

### 2.1 服务规模与拆分粒度

字节是 **国内微服务拆分最细的公司之一**：

- **微服务总数**：内部预估 **5000–10000+** 个微服务（公开演讲披露，2024 年 GMTC 数据为单业务线超过 3000 个）。字节采用"以业务功能为边界、强一致单元最小化"的拆分原则。
- **服务语言比例**：Go ~50%、Python ~25%、C++ ~15%、Java ~10%（2025 QCon 数据）。
- **二线业务**：抖音/TikTok、电商、直播、教育、本地生活均独立 BU，独立部署独立技术栈，但共享底层 PaaS（部署、监控、配置中心）。

### 2.2 流量调度架构

1. **入口层**：BFE/API 网关层支持 HTTP/3、QUIC、TLS 1.3，**全网 HTTPS 卸载**，抖音 App 默认启用 QUIC（减少弱网延迟）。
2. **边缘加速**：自研 CDN + 边缘计算节点，全球 100+ 国家 1000+ PoP。
3. **微服务调用**：内部服务 99% 通过 Kitex/Hertz 调用，少量 gRPC。
4. **智能路由**：基于用户地理位置、网络质量、机房健康度的多目标调度（参考 Google Maglev 思路）。

### 2.3 服务网格与多运行时

- **Mesh 化进度**：内部已 **大规模落地 Service Mesh**，基于 Envoy/Istio 做核心扩展（项目内部代号 Aeraki Mesh，已开源）。
- **多运行时 (Dapr) 思路**：在 Service Mesh 之外，引入 WASM 作为 sidecar 扩展机制，支持自定义流量策略（2024 公开技术分享）。
- **可观测性**：链路追踪用 Btrace/OpenTelemetry，指标采集用 Prometheus+Grafana，日志用自研 LogPipeline。

## 三、多机房多活架构（异地多活）

### 3.1 部署拓扑

字节的机房分布是 **"三地四中心 + 海外大区"**：

- **国内主中心**：北京（核心交易）、上海（推荐/AI）、深圳（电商）
- **海外**：新加坡（亚太中转）、法兰克福（欧洲）、弗吉尼亚（北美东）、达拉斯（北美中）、圣保罗（南美）
- **Edge**：全球 1000+ 边缘节点

### 3.2 多活方案

字节是国内 **最早实现"单元化 (Cell-based) 多活"** 的公司之一（2018 年起，2023 完成 7 级单元化升级）：

1. **数据层**：MySQL 采用 **双主+DRC（自研数据复制中间件）** 实现跨机房同步，单元内本地读写，单元间通过路由层转发。
2. **流量调度**：基于用户 ID 哈希 + 机房健康度，将用户绑定到固定单元（单元大小可控）。
3. **容灾**：单机房故障可秒级切流（2024 年某次机房断电事故中实现 8 秒切流）。
4. **海外特殊挑战**：
   - **合规**：GDPR/CCPA/东南亚数据本地化要求数据不出境 → 采用 **"区域级单元化 + 数据分区"**。
   - **延迟**：海外 PoP 节点到中心机房 RTT 100ms+ → 在边缘完成 Feed 排序、CDN 分发。
   - **TikTok vs 抖音**：技术栈 90% 共享，**抖音电商 (Douyin E-commerce)** 独立技术栈，因为涉及支付/库存/履约，与内容分发隔离。

### 3.3 数据库多活

- **MySQL**：自研分布式中间件（DRC），支持 Binlog 实时订阅 + 多向同步 + 冲突检测。
- **TiDB**：用于全球账务、订单等强一致场景（已通过 POC）。
- **OceanBase**：部分金融业务使用（电商支付链路）。

## 五、字节 AI/ML 平台

### 5.1 训练基础设施

- **Megatron-DeepSpeed 改进版**：字节在 NVIDIA Megatron 基础上自研 veGiantModel，2024 年公开 **万卡级 LLM 训练集群**（单集群 1万+ H100/A100），技术报告发布在 arXiv。
- **BytePS**：2019 年开源，分布式训练参数服务器，比 Horovod 在 100+ GPU 规模下提升 1.5–5x，目前仍是字节内部主力。
- **MegaScale**：2024 年披露的万卡训练框架，专门解决 LLM 训练中的通信/调度/容错问题（论文：MegaScale: Scaling Large Language Model Training to Multiple Tens of Thousands of GPUs, ByteDance 2024）。
- **veGiantModel**：字节自研 LLM（豆包 / Doubao / Skymind）训练平台（2024 CVPR/ICLR 论文披露）。

### 5.2 推荐系统：Monolith

详见 `02-推荐系统与Monolith.md`

### 5.3 特征平台与推理

- **Feature Store**：自研 **FeatureStore (Feast 兼容)**，支持在线/离线一致性，TikTok/抖音 Feed 排序服务全部基于该平台。
- **在线推理**：基于 **TensorRT + 自研 ByteML**，P99 延迟 < 50ms。
- **LLM 推理**：2024 年发布 **ByteTransformer**（GitHub 开源），针对 H100/A100 优化。
- **多模态**：视频理解用 MMDiT，文本/图像/音频统一表征。

### 5.4 LLM 应用编排：eino

**CloudWeGo/eino**（⭐11.9k）是字节的 **LLM 应用编排框架**：

- 类似于 LangChain/LlamaIndex，但更偏 Go 生态。
- 核心是 **Graph + Component** 抽象，支持 ReAct/Plan-Execute/Reflection 等 Agent 模式。
- 配套 eino-ext 提供 50+ 组件（Tool、Retriever、Loader）。

## 六、数据库选型

字节的数据库策略是 **"多引擎并存 + 场景驱动"**：

| 场景 | 选型 | 备注 |
|---|---|---|
| OLTP 核心交易 | **MySQL + 自研中间件** | 主库 TiDB/MySQL，从库 OceanBase |
| 分布式事务 | **TiDB** | 电商订单/支付 |
| 强一致账务 | **OceanBase** | 金融级场景 |
| KV 缓存 | **Redis + 自研 KV (Abase)** | Abase 单机 100w QPS |
| 搜索引擎 | **Elasticsearch (内部增强版)** | 视频搜索/电商搜索 |
| 时序/指标 | **自研 Bitable + Druid** | 监控/广告 |
| 离线数仓 | **Hive + Spark + ByteHouse** | PB 级 |
| 实时数仓 | **Kafka + Flink + ByteHouse** | 推荐/广告 |
| 湖仓 | **Iceberg + Hudi + 自研** | 2024 起重点投入 |
| HTAP | **TiDB + ClickHouse** | 部分场景 |

### 6.1 ByteHouse 详解

ByteHouse 是字节 **基于 ClickHouse 的增强版 OLAP**：

- 改造点：增加分布式协调、自研 Catalog、向量索引、存算分离（参考 Snowflake 架构）。
- 规模：字节内部单集群 **万+ 节点**（2024 InfoQ 披露）。
- 商业化：火山引擎对外售卖，社区版部分开源（github.com/bytehouse-cloud）。

### 6.2 自研存储

- **HDFS**：核心存储，EB 级。
- **对象存储**：自研 **BOS (Byte Object Storage)**，兼容 S3 协议。
- **冷存储**：自研低频存储，成本降至 S3 IA 1/3。

## 七、抖音电商、TikTok 海外特有架构

### 7.1 抖音电商

抖音电商是 **字节内部技术体系最复杂的业务**：

- **供应链**：单独 ERP + WMS + TMS，与内容分发解耦。
- **履约**：电子面单系统每日处理亿级订单。
- **支付**：抖音支付独立金融云牌照，自有支付 + 银联/支付宝多通道。
- **直播电商**：实时音视频（自研 RTC）+ 实时推荐（Monolith）+ 实时互动（IM 即时通讯）。

### 7.2 TikTok 海外架构

TikTok 与抖音 **代码同源、部署独立**，技术差异：

| 维度 | 抖音 | TikTok |
|---|---|---|
| 数据中心 | 国内 | 新加坡/欧洲/美国多区域 |
| 合规 | 中国法规 | GDPR/CCPA/各国本地化 |
| 支付 | 抖音支付/微信/支付宝 | Stripe/PayPal/本地支付 |
| 推荐 | 同 Monolith | 独立模型（数据隔离） |
| 直播带货 | 主推 | TikTok Shop（2024–2026 重点） |
| CDN | 自研 + 阿里云/腾讯云 | 自研 + AWS/Google Cloud |

**TikTok Shop** 是 2024–2026 字节增长最快的业务，2025 年 GMV 超过 200 亿美元（公开报道），技术栈：

- **全栈云原生**：100% K8s + 自研 Operator。
- **多云**：AWS 为底座 + Google Cloud 灾备 + 自建边缘。
- **WASM 中间件**：在 Service Mesh 中通过 WASM 实现合规过滤（不同地区不同策略）。
- **多活**：单元化级别比抖音电商更高（5 级单元）。

### 7.3 海外部署的特有挑战

1. **延迟**：北美 PoP 到中心机房 200ms+，必须边缘推理（推荐模型裁剪到 100ms 以内）。
2. **合规**：TikTok 美国数据本地化（Project Texas 计划，Oracle 运营），所有美国用户数据物理隔离。
3. **带宽**：海外带宽成本是国内的 3–5x，TikTok 大量自研编码器（如 ByteVideo Codec）。
4. **本地化**：每个国家一套推荐模型（小语种+本地热点），AI 推理节点下沉到区域。

## 八、总结与可观测性建议

字节的技术栈演进有三条清晰主线：

1. **2018–2022**：自研基础设施期（Kitex/Hertz/Sonic/Netpoll/Monolith/ByteHouse）
2. **2023–2024**：AI 转型期（豆包大模型、eino、deer-flow、UI-TARS）
3. **2025–2026**：Agentic AI 爆发期（trae-agent、UI-TARS-desktop、字节内部 80% 工程师使用 AI 编程）

对于跨境电商技术决策的启示：

- **可借鉴**：Kitex/Hertz/Sonic 的微服务标准、单元化多活架构、Monolith 实时训练。
- **可学习**：eino 编排范式、deer-flow 长任务 Agent 模式。
- **TikTok Shop 重点**：多区域单元化、合规边缘计算、实时音视频互动。
