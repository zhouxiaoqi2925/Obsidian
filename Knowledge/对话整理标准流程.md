# 🔄 Claude Code 对话整理标准流程

## 执行时机

每次对话/开发任务结束时，Claude Code **必须**按以下顺序整理知识库：

## 📋 标准流程

### 第一步: 生成思维导图 🧠

**目标**: 先理清整体结构，可视化展示

**产出**: `Sessions/YYYY-MM-DD-mindmap.md`

**格式要求**:
- 使用 `## ### ####` 层级结构（兼容 Enhancing Mindmap 插件）
- 覆盖：做了什么 → 怎么做的 → 关键决策 → 踩坑 → 项目关联
- 每个节点简洁（不超过 20 字）
- 在 Obsidian 中打开后可用 Enhancing Mindmap 可视化

### 第二步: 写入知识库 📚

**目标**: 基于思维导图，展开详细内容

**产出清单**:

| 优先级 | 文件 | 内容 |
|--------|------|------|
| P0 | `Daily/YYYY-MM-DD.md` | 每日开发日志（完整记录） |
| P0 | `Sessions/YYYY-MM-DD.md` | 对话摘要 + 关键决策 |
| P1 | `Projects/{项目}/overview.md` | 更新项目进展 |
| P1 | `Projects/_index.md` | 更新总览时间戳 |
| P2 | `Knowledge/{主题}.md` | 提取可复用知识卡片 |
| P2 | `Wiki/{分类}/{词条}.md` | 新知识写入 Wiki |

### 第三步: 索引更新 🔗

- 更新 Wiki 索引 (`Wiki/_index.md`)
- 关联相关笔记（双链 `[[...]]`）
- 更新 frontmatter 标签

## 🚫 禁止行为

- ❌ 只写详细文档不写思维导图
- ❌ 思维导图过于简略（< 10 个节点）
- ❌ 跳过 Daily 日志
- ❌ 知识只存在对话里不写入 Obsidian

## ✅ 质量标准

- 思维导图至少 15+ 节点，覆盖完整
- Daily 日志包含：完成事项、技术细节、踩坑、文件清单
- 项目页保持更新（状态、进度、待办）
- 所有文件包含正确的 frontmatter (tags, date, status)

---

> 🤖 此规则对 Claude Code 具有约束力，每次对话结束自动执行
