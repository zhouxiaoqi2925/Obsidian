# Claude Skills - 工作原理与架构

## 1. Skill 的本质

**Skill** 是一个**带元数据的指令包**，Claude 在对话中会根据：
1. Skill 的 `description` 字段（触发词）
2. 用户的请求内容
3. Skill 的工作流定义

**自动选择**最合适的 Skill 来执行任务。

## 2. Skill 文件的标准结构

每个 Skill 必须有 `SKILL.md` 文件，使用 YAML frontmatter：

```markdown
---
name: skill-name                    # 必填，Skill 名称
description: Use when user asks to... # 必填，触发描述
---

# Skill 标题

## 概述
（这个 Skill 做什么）

## 工作流
（步骤 1、2、3...）

## 关键规则
（强制规范、不能违反的红线）

## 输入输出
（用户提供什么，Skill 产出什么）

## 示例
（真实调用案例）
```

## 3. 一个 Skill 目录的完整结构

```
skills/
└── database-designer/              # Skill 目录
    ├── SKILL.md                    # ⭐ 核心指令文件（必填）
    ├── README.md                   # 可选：补充说明
    ├── references/                 # 可选：参考文档
    │   ├── database-selection-decision-tree.md
    │   ├── index-strategy-patterns.md
    │   └── normalization-guide.md
    ├── scripts/                    # 可选：Python 工具脚本
    │   ├── schema_analyzer.py
    │   ├── index_optimizer.py
    │   └── migration_generator.py
    ├── assets/                     # 可选：模板、示例数据
    │   ├── sample_query_patterns.json
    │   └── sample_schema.sql
    ├── expected_outputs/           # 可选：期望输出样例
    └── evals.json                  # 可选：评估指标
```

## 4. Skill 的工作流原理

### 4.1 Claude 收到请求时
1. 扫描所有可用 Skill 的 `description` 字段
2. 用语义匹配判断哪个 Skill 最相关
3. 读取该 Skill 的 `SKILL.md`
4. 按 Skill 定义的工作流执行
5. 必要时调用 `scripts/` 下的 Python 工具

### 4.2 Skill 工作流的典型模式

**模式 A：单步执行**
```
用户请求 → SKILL.md → 直接执行 → 输出
例：code-simplifier（读代码 → 重写）
```

**模式 B：多步流水线**
```
用户请求 → Step 1 → Step 2 → Step 3 → 输出
例：spec-driven-workflow（写 spec → 评审 → 实施 → 测试）
```

**模式 C：多 Agent 协作**
```
用户请求 → Agent 1 ─┐
        → Agent 2 ─┼→ 综合结果
        → Agent 3 ─┘
例：code-review（5 个并行 agent 独立审查 → 评分过滤）
```

**模式 D：外部工具调用**
```
用户请求 → SKILL.md → 调用 Python 脚本 → 处理 → 输出
例：database-designer（调用 schema_analyzer.py）
```

## 5. YAML Frontmatter 字段详解

### 必填字段

| 字段 | 含义 | 示例 |
|------|------|------|
| `name` | Skill 唯一标识 | `database-designer` |
| `description` | 触发描述，Claude 用它来匹配用户请求 | `Use when the user asks to design a database schema, normalize tables, or optimize indexes` |

### 可选字段

| 字段 | 含义 |
|------|------|
| `version` | Skill 版本 |
| `author` | 作者 |
| `tags` | 标签 |
| `dependencies` | 依赖的其它 Skill |

## 6. Skill 的"自动调用"机制

### 6.1 触发词匹配

**核心机制**：Skill 的 `description` 字段就是它的"触发词"。

**例子**：
- `database-designer` 的 description：`Use when the user asks to design a database schema, optimize indexes, or normalize tables.`
- 当用户说"帮我设计一个用户表的 schema" → Claude 匹配 → 调用

### 6.2 触发词的写法

✅ **好的写法**（具体、可触发）：
```
Use when the user asks to design database schemas, optimize indexes,
generate migration scripts, or normalize database tables.
```

❌ **不好的写法**（太宽泛、不具体）：
```
A skill for databases.
```

### 6.3 我们的自动调度规则

我们配置的自动调度规则（在 [[02-自动调度规则]] 中详述）：

```
1. 用户说一句话描述需求
2. Claude 识别需求关键词
3. 在知识库中匹配最合适的 1-3 个 Skill
4. 按 Skill 的工作流执行
5. 必要时调用 Skill 自带的 Python 工具
6. 输出符合 Skill 标准的结果
```

## 7. Skill 与 Agent 的区别

| 维度 | Skill | Agent |
|------|-------|-------|
| **触发方式** | 用户请求匹配 description | 显式调用（如 Task tool） |
| **复杂度** | 中等（执行一个工作流） | 高（自主决策 + 多步推理） |
| **上下文** | 加载 SKILL.md 指令 | 加载 AGENT.md 系统提示 |
| **工具** | 可用 scripts/ 下的脚本 | 可用所有工具 + 其它 Agent |
| **并行** | 单个 Skill 执行 | 多个 Agent 可并行 |

**典型组合**：
- `code-review` Skill 调用 `code-reviewer` Agent
- `feature-dev` Skill 包含 `code-architect`、`code-explorer`、`code-reviewer` 三个 Agent

## 8. Skill 的版本管理

每个 Skill 通过 `version` 字段管理版本：
- `1.0.0` — 初始版本
- `1.1.0` — 添加新功能
- `2.0.0` — 重大重构

我们知识库中记录的版本信息来自：
- `claude-skills/.claude-plugin/marketplace.json` 中的 metadata.version
- SKILL.md 的 frontmatter
- 仓库的 Git tags

## 9. Skill 的安全模型

### 9.1 三层防护

1. **Skill 自身的 guardrails**（SKILL.md 中的"必做/必不做"）
2. **skill-security-auditor Skill**（专门审查 Skill 的安全性）
3. **trailofbits/skills**（安全专精，由 Trail of Bits 维护）

### 9.2 已部署的安全 Skill

- `security-guidance` — Claude 写代码时的安全提醒
- `skill-security-auditor` — Skill 自身的安全审查
- `trailofbits/property-based-testing` — 基于属性的测试
- `trailofbits/semgrep-rule-creator` — Semgrep 规则创建
- `trailofbits/cosmos-vulnerability-scanner` — 区块链漏洞扫描

## 10. 总结

- Skill = 带元数据的工作流定义 + 可选工具脚本
- Claude 通过 description 自动匹配 Skill
- 每个 Skill 都有标准化的目录结构
- Skill 与 Agent 互补，常组合使用
- 知识库已收录 1000+ 个生产就绪的 Skill
