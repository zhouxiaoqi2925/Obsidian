## 1. 领域定位

**适用场景**：
- 后端开发（任何语言）
- 前端开发
- 数据库设计
- 运维 / DevOps / SRE
- 性能优化
- 安全审计

- 技术债管理

## 4. 关键技术亮点

### 4.1 Spec-Driven Development
- 强制先写规格再写代码
- 9 个强制章节（Context/Requirements/Acceptance/Edge Cases/API/Data Models/Out of Scope...）
- RFC 2119 关键词（MUST/SHOULD/MAY）
- Acceptance Criteria 用 Given/When/Then

### 4.2 Iron Law
来自 spec-driven-workflow：
> NO CODE WITHOUT AN APPROVED SPEC.
> NO EXCEPTIONS. NO "QUICK PROTOTYPES." NO "I'LL DOCUMENT IT LATER."

### 4.3 Karpathy 编码规范
- 假设验证（assumption_linter）
- 复杂度检查（complexity_checker）
- Diff 外科手术（diff_surgeon）
- 目标验证（goal_verifier）

### 4.4 Zero Hallucination
- 强制溯源
- 每行代码必须能追溯到 spec 中的某条 requirement
- 禁止"应该这样"、必须"确实如此"

## 5. 怎么选择

### 5.1 按场景选择

| 你的需求 | 推荐 Skill |
|---------|-----------|
| 开始新功能 | spec-driven-workflow + database-designer + api-design-reviewer |
| 写数据库 | database-designer |
| 写 API | api-design-reviewer + api-test-suite-builder |
| 部署 | ci-cd-pipeline-builder + docker-development + kubernetes-operator |
| 监控 | observability-designer + slo-architect |
| 性能问题 | performance-profiler + chaos-engineering |
| 安全审计 | security-guidance + secrets-vault-manager |
| 接手项目 | codebase-onboarding + code-tour |
| 写 Skill | write-a-skill + skill-tester |
| 发布 | ship-gate |

### 5.2 按成熟度选择

- **新项目（0→1）**：spec-driven-workflow → database-designer → api-design-reviewer → ci-cd-pipeline-builder
- **已有项目（1→10）**：codebase-onboarding → code-review → performance-profiler → observability-designer
- **生产环境（10→∞）**：slo-architect → chaos-engineering → ship-gate → postmortem-facilitator
