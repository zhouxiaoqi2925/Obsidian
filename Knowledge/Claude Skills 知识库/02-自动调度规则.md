# Claude Skills 自动调度规则

## 1. 核心理念

**用户不需要记任何 Skill 名字**。当你说一句话描述需求，Claude 会自动：
1. 识别需求类型
2. 在 1000+ 个 Skill 中挑选最合适的
3. 读取该 Skill 的 SKILL.md
4. 按 Skill 定义的工作流执行
5. 输出符合标准的结果

## 2. 自动调度的 6 步流程

```
Step 1: 意图识别
   ↓ 把用户的话分解成"做什么 + 在什么场景 + 要什么输出"
Step 2: Skill 匹配
   ↓ 用 description 字段做语义匹配，挑出 1-3 个候选
Step 3: 加载 Skill 指令
   ↓ 读取候选 Skill 的 SKILL.md
Step 4: 选择工作流
   ↓ 根据 Skill 的工作流类型（单步/多步/多 Agent/外部工具）
Step 5: 执行
   ↓ 按工作流执行，必要时调用 scripts/ 下的 Python 脚本
Step 6: 输出验证
   ↓ 按 Skill 标准验证输出（如果 Skill 有 evals.json）
```

### 3.2 多 Skill 组合规则

**复杂任务**需要多个 Skill 串联：

```
完整开发流程：
  spec-driven-workflow → codebase-onboarding → database-designer →
  api-design-reviewer → feature-dev → api-test-suite-builder →
  code-review → ship-gate

安全审计：
  spec-driven-workflow → security-guidance →
  trailofbits/property-based-testing → trailofbits/semgrep-rule-creator →
  ship-gate

性能优化：
  observability-designer → performance-profiler →
  database-designer → chaos-engineering → ship-gate
```

## 4. Skill 匹配优先级

当多个 Skill 匹配时，按以下优先级选择：

1. **精确匹配** — description 中关键词与用户意图完全吻合
2. **领域匹配** — 同一领域的 Skill 优先
3. **组合优先** — 能组合解决完整问题的优先
4. **官方优先** — claude-plugins-official 的 Skill 优先于社区
5. **新版本优先** — 同名 Skill 选版本新的

## 5. Skill 调用失败的处理

如果自动调度的 Skill 失败：
1. **降级** — 切换到更通用的 Skill
2. **拆分** — 把任务拆成多个小任务，分别调用不同 Skill
3. **询问** — 如果仍无法匹配，向用户询问澄清

## 6. 用户控制（高级）

虽然默认全自动，但你可以干预：

### 6.1 显式指定 Skill
```
用 code-review 技能审查这段代码
用 database-designer 技能设计 schema
```

### 6.2 禁用某个 Skill
```
不要用 xxx 技能
```

### 6.3 强制使用某个 Skill
```
必须用 ship-gate 技能检查完才能发布
```

## 7. 调度示例

### 示例 1：用户说"帮我设计一个用户表"

**Claude 自动识别**：
- 意图：数据库设计
- 场景：用户表（很常见的场景）
- 期望输出：schema + 索引 + 迁移脚本

**自动调用**：
1. `spec-driven-workflow` — 先写规格（如果是大改）
2. `database-designer` — 主调用
   - 调用 `schema_analyzer.py` 分析现有 schema
   - 调用 `index_optimizer.py` 优化索引
   - 调用 `migration_generator.py` 生成迁移

### 示例 2：用户说"我的 API 慢了，帮我优化"

**Claude 自动识别**：
- 意图：性能优化
- 场景：API（HTTP 接口）
- 期望输出：优化方案 + 实施步骤

**自动调用**：
1. `performance-profiler` — 主调用
2. `observability-designer` — 检查 SLO/SLI 是否合理
3. `database-designer` — 检查是否有索引缺失
4. `code-review` — 检查代码是否有性能反模式

### 示例 3：用户说"我要做 RAG 系统"

**Claude 自动识别**：
- 意图：架构设计
- 场景：RAG（检索增强生成）
- 期望输出：完整架构 + 实施计划

**自动调用**：
1. `spec-driven-workflow` — 先写规格
2. `rag-architect` — 主调用
   - 调用 `chunking_optimizer.py` 设计分块策略
   - 调用 `rag_pipeline_designer.py` 设计 pipeline
   - 调用 `retrieval_evaluator.py` 评估检索质量
3. `observability-designer` — 设计监控

## 8. 性能保证

- 单 Skill 加载时间：< 1 秒
- 多 Skill 组合：< 3 秒
- Python 工具调用：取决于脚本复杂度
