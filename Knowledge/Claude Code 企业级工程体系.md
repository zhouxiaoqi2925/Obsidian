## 第一篇：企业级架构设计与开发规范

### 1. 框架总体设计

#### 1.1 四层微内核技术架构

```
┌─────────────────────────────────────────────────────┐
│                    接入层 (Interface Layer)           │
│  CLI / Web / RESTful API / 管理后台 / 第三方集成网关  │
├─────────────────────────────────────────────────────┤
│                    业务层 (Business Layer)            │
│ 学习流程引擎 / 代码评测 / 任务管理 / 进度追踪 / 评分  │
├─────────────────────────────────────────────────────┤
│                    AI能力层 (AI Core Layer)           │
│  Claude客户端 / Prompt模板引擎 / 代码解析 / 响应调度   │
├─────────────────────────────────────────────────────┤
│                 基础设施层 (Infra Layer)              │
│ 配置中心 / 日志 / 缓存 / 安全沙箱 / 异常中心 / 工具集  │
└─────────────────────────────────────────────────────┘
```

#### 1.2 核心模块拆解

| 模块名称 | 归属层级 | 核心能力 |
|---------|----------|----------|
| 接入网关模块 | 接入层 | 多端统一接入、请求路由、限流熔断 |
| 权限与多租户模块 | 接入层 | RBAC、租户数据隔离、配额管理、OAuth2/JWT |
| 学习业务模块 | 业务层 | 练习生成、代码评测、学习进度、知识点管理 |
| Claude 集成模块 | AI能力层 | API客户端、重试/熔断、响应校验、模型适配器抽象 |
| Prompt 模板模块 | AI能力层 | 模板管理、动态渲染、版本控制、A/B测试 |
| 代码沙箱模块 | 基础设施层 | 安全代码执行、资源限制、超时管控、逃逸检测 |
| 配置中心模块 | 基础设施层 | 多环境配置、类型安全加载 |
| 日志追踪模块 | 基础设施层 | 结构化日志、全链路追踪、Metrics指标采集 |
| 数据治理与合规模块 | 基础设施层 | 数据分类/保留/脱敏、审计日志、用户数据导出/删除 |

#### 1.3 非功能性需求

- **可用性**：99.9%，含AI服务不可用时的降级方案
- **AI接口响应超时**：≤10s
- **沙箱代码执行超时**：≤5s
- **安全性**：代码执行100%沙箱隔离、密钥零泄露
- **可扩展性**：模块支持热插拔、无侵入扩展
- **数据合规**：支持GDPR/个人信息保护法要求

### 2. 开发规范

#### 2.1 技术栈规范

- Python 3.11+、Anthropic SDK、Pydantic-settings、Poetry
- Ruff/mypy、structlog、Docker沙箱
- SBOM生成（cyclonedx）、依赖哈希锁定、镜像不可变标签

#### 2.2 接口与AI集成规范

- 统一 `ClaudeClient` 抽象协议（支持多模型适配）
- Prompt模板化+版本控制
- AI响应强校验（格式、安全、代码合法性）
- 响应质量自动化评分

#### 2.3 安全开发规范

- 密钥零硬编码
- 沙箱禁止非必要系统调用
- 网络白名单策略
- 日志脱敏
- 依赖漏洞扫描融入CI
- 定期SAST

#### 2.4 CI/CD门禁

- Ruff + mypy + 测试覆盖率
- 安全扫描（bandit/semgrep）
- SBOM + 容器构建
- 禁止AI直接推送保护分支

## 第二篇：开发者能力成长框架

### 一、核心能力雷达模型（6维度）

1. **上下文工程**：精准提取、裁剪、投喂项目信息
2. **提示词架构**：将模糊业务需求转化为结构化机器指令
3. **架构把控与审查**：识别AI代码中的设计缺陷、安全漏洞
4. **验证与测试驱动**：构建自动化验证网让AI自我纠错
5. **智能体编排**：利用Hooks、MCP、Headless模式融入CI/CD
6. **安全与合规内建**：威胁建模、沙箱化验证、合规意识

### 二、四阶演进学习路径

| 阶段 | 名称 | 核心技能 | 通关标准 |
|------|------|----------|----------|
| L1 | 破冰者 | 基础交互、单文件任务、修复简单Bug | 能独立完成单文件修改 |
| L2 | 驾驭者 | 标准工作流（CLAUDE.md、Plan Mode、TDD） | 首次通过率≥60% |
| L3 | 架构师 | 跨文件重构、复杂调试、自定义Hooks、MCP集成 | 安全扫描自动化 |
| L4 | 智能体工程师 | Headless模式、CI/CD深度集成、团队规范制定 | 自动化回滚率 |

### 三、人机职责边界矩阵

| 任务类型 | AI角色 | 人类角色 | 不可逾越的红线 |
|----------|--------|---------|--------------|
| 代码生成 | 主力写手 | 审查、架构决策 | AI不可独立决定架构变更 |
| 测试编写 | 主要产出者 | 场景设计、边界定义 | AI不可定义"什么构成正确" |
| 依赖库选择 | 信息提供 | 决策、安全评估 | AI不可直接修改依赖清单 |
| 数据库迁移 | 脚本生成 | 审查、备份、执行 | AI不可直接执行DDL |
| 配置修改 | 建议 | 审批、灰度 | AI不可直接修改生产环境配置 |

## 第三篇：体系化增强与长期治理

### 1. 沙箱安全深度防御

- Seccomp禁止危险系统调用
- 网络白名单（仅允许经审核的依赖源）
- AST静态分析恶意代码特征库
- 运行时资源异常飙升自动销毁并告警

### 2. 供应链安全

- SBOM：每个构建生成CycloneDX/SPDX格式物料清单
- 自动修复：Dependabot自动提PR更新漏洞依赖
- 镜像签名与不可变标签

### 3. 韧性工程与混沌测试

- 故障注入：模拟AI服务超时、返回无效JSON、沙箱OOM
- 自动回滚：当构建失败率突增，触发自动revert

### 4. 框架健康度巡检

- **Sprint巡检**：AI辅助对比CLAUDE.md与当前代码库的一致性
- **月度清理**：Prompt模式库使用率统计
- **季度复活测试**：CI/CD中AI自动化节点重新执行验证
