# 软件架构架构模式对比表

## 模式总览

| 模式 | 特点 | 适用场景 | 优缺点 |
|------|------|----------|--------|
| **单体** | 单一容器统一部署 | 简单应用 | 低成本高性能，但扩展性差 |
| **微服务** | 独立服务分布式 | 现代应用 | 便于更新测试，但复杂度高 |
| **客户端-服务器** | 请求-响应模型 | 邮件/网站 | 适合交互式服务 |
| **分层** | 多层职责分离 | 企业/电商 | 最广泛使用 |
| **事件驱动** | 实时事件处理 | 高交互电商 | 适合频繁用户操作 |

## 分层架构详解

```
┌─────────────────────────────┐
│     表现层 (Presentation)    │ ← 用户界面
├─────────────────────────────┤
│       业务层 (Business)      │ ← 业务逻辑
├─────────────────────────────┤
│      应用层 (Application)    │ ← 服务编排
├─────────────────────────────┤
│       数据层 (Data)           │ ← 数据库
└─────────────────────────────┘
```

## 事件驱动架构流程

```
事件生产者 → 事件路由 → 消费者
   ↓
用户操作触发（如：添加购物车）
   ↓
实时处理响应
```

## SOLID 原则速记

```
S - 单一职责：一个类做一件事
O - 开闭原则：扩展而不修改
L - 里氏替换：子类替换父类
I - 接口隔离：小而专的接口
D - 依赖反转：依赖抽象而非具体
```

## 架构选型指南

```
需求复杂度
    │
    高 ─────────────────→ 微服务 / 事件驱动
    │
 中等 ─────────────────→ 分层架构
    │
    低 ─────────────────→ 单体架构
```

## 关键术语

- **SDLC**: Software Development Lifecycle 软件开发生命周期
- **UML**: Unified Modeling Language 统一建模语言
- **组件 (Component)**: 可替换的构建块
- **接口 (Interface)**: 组件间通信点
- **耦合 (Coupling)**: 模块间依赖程度
- **内聚 (Cohesion)**: 模块内部联系程度
