# OpenLive H2 2026 升级路线图

> 来源：两轮深度测试后整理的内部升级建议。
> 对应本仓库代码位置：`G:\ai-live-platform`

---

## 一、架构层（最优先）

| # | 模块 | 现状 | 升级方案 | 工时 |
|---|------|------|----------|------|
| 1 | **GORM AutoMigrate** | 启动失败 `insufficient arguments` | 改用 Atlas 版本化迁移 + 幂等检查 | 1d |
| 2 | **Python AI 服务** | 完全未集成，docker-compose 没编排 | 拆出独立服务 + Dockerfile + K8s Deployment | 2d |
| 3 | **单体后端** | 全部业务耦合在 `ai-live-backend.exe` | 拆 API 网关 + 4 微服务（直播/订单/支付/AI） | 5d |
| 4 | **配置中心** | `config.yaml` 硬编码，4 平台 OAuth 占位符 | 接入 Nacos/Consul，支持热更新 | 2d |
| 5 | **消息队列** | 直播事件无异步通道 | 引入 RabbitMQ/Kafka（开播/打赏/订单/AI回调） | 3d |
| 6 | **分布式追踪** | 仅有 stdout 日志，无链路追踪 | OpenTelemetry → Jaeger/Tempo | 2d |
| 7 | **缓存层** | Redis 仅作 session | 加多级缓存（本地 LRU + Redis + 热点数据预热） | 2d |

## 三、安全层

| # | 模块 | 现状 | 升级方案 | 工时 |
|---|------|------|----------|------|
| 1 | **RASP strictMode** | 默认 `false`，仅记录不阻断 | 默认 `true` + 灰度开关 + 告警 | 0.5d |
| 2 | **JWT 算法** | HS256 + 占位符 secret | RS256 非对称 + 短期 access + 长期 refresh + 自动旋转 | 1d |
| 3 | **/health 信息泄露** | 暴露 service/version/timestamp | 改为 `/health` 返回简单 ok，`/health/detail` 鉴权后返回详情 | 0.2d |
| 4 | **CORS 动态白名单** | hardcode 3 个地址 | 读环境变量 + 数据库动态配置 | 0.5d |
| 5 | **DB SSL** | `sslmode: disable` | 生产 `require` + 证书校验 | 0.5d |
| 6 | **二次验证** | 无 | 开播/退款/导出 强制 OTP + 手机验证 | 2d |
| 7 | **审计日志** | 部分接口有 log | 全链路审计（操作/接口/数据变更 → ES + Kibana） | 3d |
| 8 | **客户端 SSL Pinning** | Electron 无 | 加 `pin-sha256` 防中间人 | 1d |
| 9 | **密钥管理** | 写死 `Admin@123456` 等 | KMS / Vault 集中管理 + 自动轮换 | 3d |
| 10 | **DDoS/WAF** | 无 | 接 CDN（WAF）+ nginx limit_req + fail2ban | 2d |

## 🎯 升级节奏（2026 H2）

### 第一阶段（本月 1-2 周）：打通核心链路
- 修 3 个 P0 + 5 个 P1（合计 ~7d）
- 加 /metrics + /health 真实检查（1d）

### 第二阶段（Q3）：业务上线
- Python AI 服务独立化（2d）
- 多平台同步直播 MVP（5d）
- 数字人主播集成（5d）
- Flutter 移动 App MVP（10d）

### 第三阶段（Q4）：规模化
- 微服务拆分 + K8s（10d）
- 监控告警体系完善（5d）
- 智能话术/选品/风控（8d）
- 多语言 + 海外 CDN（5d）
