# Obsidian + AI 开发技术知识库｜搭建指南

> 本指南基于现有 Obsidian 库 `G:\Obsidian Vault\` 落地，结合本地 AI（Claude Code / DeepSeek 插件）实现开发知识库智能化。

## 一、为什么用 Obsidian 做开发知识库

### 1. 全本地存储
所有开发笔记、学习文档、技术方案、代码片段全部以本地 Markdown 文件存放，不联网、不上云，数据完全自己掌控。

### 2. Markdown 天生适配开发 + AI
开发文档、接口文档、技术笔记本来就是 Markdown 格式。Claude、GPT、本地大模型可直接读取本地文件夹所有技术笔记。

### 3. 双向链接 + 知识图谱
Java、Python、Linux、数据库、框架知识点互相关联；AI 能梳理技术脉络、查漏补缺。

### 4. 可做 AI 长期开发记忆库
新建固定笔记记录：技术栈、学习进度、项目经验、常用配置、踩坑记录；以后问 AI 自动带入技术背景。

### 5. 插件生态适配开发
代码高亮、代码片段管理、接口文档、思维导图、架构图、目录自动生成。

## 二、底层工作原理

### 1. 存储层面
Obsidian 本质就是本地文件夹 + Markdown 文档，没有私有加密格式，任何程序、AI、脚本都能直接读取。

### 2. AI 交互层面
大模型直接读取本地整个技术库文件夹，理解代码片段、技术原理笔记、架构文档、报错方案，然后做总结、答疑、梳理、写代码、排错。

### 3. 知识结构层面
双向链接把零散知识点连成体系，AI 识别技术关联、知识点缺失，自动补全学习路线。

## 三、本库已落地的目录结构

```

├── Wiki/

│   └── Claude/            ← Claude Code 相关
├── 开发手册/              ← 第三方开发手册导航（System Design / Clean Code / RESTful...）
├── 实战案例/              ← 大厂实战（Amazon / Netflix / Google / Uber...）
├── Knowledge/             ← 知识沉淀（架构 / 微服务 / Obsidian 配置 / AI 提示词）
├── Projects/              ← 项目索引（AI 直播 / Nexus Terminal / TK 电商...）
├── Daily/                 ← 日常笔记
└── Sessions/              ← 会话记录
```

## 六、统一使用规范

### 文件命名
`技术点-核心主题-日期`，例如：`Java-JVM-内存模型-20260601`

### Frontmatter 必填项
```yaml
---
tags: [...]
type: tech-note | debug-record | project-note
created: 2026-06-01
category: ...
---
```

### 标签体系
- **技术栈**：`#Java` `#Python` `#Go` `#Rust`
- **方向**：`#后端开发` `#前端开发` `#运维` `#DevOps`
- **笔记类型**：`#学习笔记` `#报错排查` `#项目实战` `#踩坑`
- **状态**：`#open` `#fixed` `#WIP`

### 代码块
所有代码、命令、配置必须用代码块包裹，并标注语言：` ```java ` ` ```bash ` ` ```yaml `

### 关联笔记
每篇笔记至少 3 个双向链接 `[[笔记名]]`，形成知识网。

## 七、AI 维护系统

详见 [[AI知识库维护系统提示词]]

核心规则：每新增笔记 → AI 精简冗余 → 补全底层原理 → 自动建双向链接 → 查漏补缺。

## 八、日常使用流程

1. **学新技术** → 调 `tech-general` 模板 → 写原理 + 代码 + 踩坑
2. **遇报错** → 调 `debug-record` 模板 → 记录现象 + 根因 + 修复
3. **做项目** → 调 `project-architecture` 模板 → 梳理架构 + 技术栈
4. **每周维护** → 调 AI 帮你：精简冗余 + 补全盲区 + 整理学习路线

- ✅ 学新技术、面试、做项目、排错，直接在库内检索 + AI 辅助
